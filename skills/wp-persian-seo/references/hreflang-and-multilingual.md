# hreflang و سایت چندزبانه

---

## 1) کدهای درست

| زبان/منطقه | کد درست | اشتباه رایج |
|---|---|---|
| فارسی (عمومی) | `fa` | `fa-FA` ❌ |
| فارسی ایران | `fa-IR` | `fa-IRN` ❌ |
| دری افغانستان | `fa-AF` یا `prs-AF` | `da-AF` ❌ |
| انگلیسی عمومی | `en` | |
| انگلیسی آمریکا | `en-US` | |
| عربی | `ar` | |
| کردی سورانی | `ckb` | `ku` ⚠️ مبهم |
| آذری | `az` یا `azb` (آذری جنوبی) | |

قاعده: کد زبان طبق ISO 639-1، کد منطقه طبق ISO 3166-1 alpha-2. `fa-FA` وجود ندارد چون `FA` کد کشور نیست.

---

## 2) ساختار صحیح

هر صفحه باید به **همه‌ی نسخه‌ها از جمله خودش** اشاره کند.

```html
<link rel="alternate" hreflang="fa-IR" href="https://example.ir/fa/cache-guide/" />
<link rel="alternate" hreflang="en"    href="https://example.ir/en/cache-guide/" />
<link rel="alternate" hreflang="ar"    href="https://example.ir/ar/cache-guide/" />
<link rel="alternate" hreflang="x-default" href="https://example.ir/en/cache-guide/" />
```

قواعد سخت:
- **self-reference الزامی است** — صفحه‌ی فارسی باید hreflang فارسی خودش را هم داشته باشد.
- **دوطرفه** — اگر A به B اشاره می‌کند، B هم باید به A اشاره کند. یک‌طرفه = نادیده گرفته می‌شود.
- URLها **مطلق** و **canonical** باشند.
- `x-default` برای صفحه‌ی پیش‌فرض/انتخاب زبان.
- canonical هر صفحه به **خودش**، نه به نسخه‌ی زبان دیگر.

---

## 3) ساختار URL

| روش | مثال | نکته |
|---|---|---|
| زیرپوشه | `example.ir/en/` | ✅ توصیه‌شده؛ ساده، اعتبار دامنه مشترک |
| زیردامنه | `en.example.ir` | ⚠️ اعتبار جدا، پیکربندی بیشتر |
| دامنه‌ی مجزا | `example.com` | برای برند جداگانه |
| پارامتر | `?lang=en` | ❌ اجتناب کن |

برای سایت فارسی با نسخه‌ی انگلیسی، **زیرپوشه** بهترین انتخاب است.

---

## 4) افزونه‌ها

### Polylang
- hreflang را خودکار می‌زند.
- بررسی کن زبان پیش‌فرض در URL نمایش داده می‌شود یا نه (`Hide URL language information for default language`) — اگر مخفی است، مطمئن شو hreflang هنوز به URL درست اشاره می‌کند.
- برای هر زبان یک صفحه‌ی اصلی جدا تعریف کن.

### WPML
- `SEO Options → hreflang` را بررسی کن.
- اگر ترجمه‌ی صفحه‌ای وجود ندارد، آن زبان نباید در hreflang بیاید.

### TranslatePress
- ترجمه‌ی خودکار را بدون بازبینی انسانی منتشر نکن؛ محتوای ماشینی بی‌کیفیت جریمه می‌گیرد.

---

## 5) اشتباهات رایج

| اشتباه | نتیجه |
|---|---|
| `fa-FA` | hreflang کلاً نادیده گرفته می‌شود |
| نبود self-reference | خوشه نامعتبر |
| اشاره‌ی یک‌طرفه | نادیده گرفته می‌شود |
| اشاره به URL ریدایرکت‌شده | نادیده گرفته می‌شود |
| اشاره به صفحه‌ی `noindex` | تناقض سیگنال |
| canonical بین‌زبانی | نسخه‌های دیگر از ایندکس خارج می‌شوند |
| ترجمه‌ی خودکار بدون بازبینی | کیفیت پایین، ریسک جریمه |
| ترجمه‌نشدن متادیتا و alt | نسخه‌ی دوم نیمه‌کاره |

---

## 6) اگر سایت تک‌زبانه‌ی فارسی است

hreflang **لازم نیست**. فقط:

```html
<html lang="fa-IR" dir="rtl">
```

و در Search Console نیازی به تنظیم geo-targeting نیست؛ زبان محتوا سیگنال کافی است.

استثنا: اگر مخاطب هم ایران و هم افغانستان است و محتوای متفاوتی برای هرکدام داری، آن‌وقت `fa-IR` و `fa-AF` معنا پیدا می‌کند. اگر محتوا یکی است، تفکیک نکن.

## 7) اعتبارسنجی

```bash
# استخراج hreflangها
curl -s https://example.ir/fa/cache-guide/ | grep -o '<link rel="alternate" hreflang="[^"]*" href="[^"]*"'

# بررسی دوطرفه بودن: همان کار را روی نسخه‌ی مقابل تکرار کن
curl -s https://example.ir/en/cache-guide/ | grep -o 'hreflang="[^"]*"'
```

سپس:
- گزارش `International Targeting` در Search Console (اگر هنوز در دسترس است)
- یک ابزار اعتبارسنجی hreflang
- بررسی دستی: هر URL در hreflang باید ۲۰۰ برگرداند و canonical خودش باشد

```
[ ] کدهای زبان معتبر (نه fa-FA)
[ ] self-reference روی هر صفحه
[ ] همه‌ی ارجاع‌ها دوطرفه
[ ] x-default تعریف شده
[ ] URLها مطلق، ۲۰۰، بدون ریدایرکت
[ ] canonical هر صفحه به خودش
[ ] متادیتا و alt هم ترجمه شده
```
